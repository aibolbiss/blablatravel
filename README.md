# Попутчик — сервис поиска попутчиков

Next.js 14 (App Router) + Supabase (Auth, Postgres, Storage, Realtime) + Leaflet.

## Возможности

- Лента объявлений на главной: фото, имя, маршрут «откуда → куда», бюджет, даты
- Страница объявления с профилем автора
- Поиск и фильтры: текст, страна, город, пол, бюджет
- Карта попутчиков (OpenStreetMap): показываются те, кто разрешил отображение локации
- Регистрация / вход (email + пароль, Supabase Auth)
- Личный кабинет: профиль «как в Facebook» (фото, био, город, пол), мои объявления
- Создание объявления с загрузкой фото и отметкой на карте
- Избранное
- Чат в стиле Discord (реалтайм через Supabase Realtime) с настройкой «разрешить писать мне»
- Row Level Security на всех таблицах

## Установка

### 1. Supabase

1. Создайте проект на [supabase.com](https://supabase.com)
2. Откройте **SQL Editor** и выполните целиком файл `supabase/schema.sql`
   (создаст таблицы, RLS-политики, триггеры, bucket `photos` и включит Realtime для чата)
3. В **Authentication → Providers → Email** можно отключить «Confirm email»,
   чтобы вход работал сразу после регистрации (для разработки)

### 2. Переменные окружения

```bash
cp .env.local.example .env.local
```

Заполните из **Project Settings → API**:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...
```

### 3. Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000

## Как работает бэкенд

Бэкенд — это Supabase: Postgres с RLS-политиками заменяет собственный API-сервер.

- **Безопасность:** каждая таблица закрыта политиками — редактировать можно только своё,
  чужие сообщения не прочитать, диалог нельзя создать с тем, кто закрыл ЛС
  (проверяется в RPC-функции `get_or_create_conversation`).
- **Чат в реальном времени:** подписка `postgres_changes` на таблицу `messages`.
- **Фото:** bucket `photos`, файлы кладутся в папку `{user_id}/...`,
  загрузка разрешена только в свою папку.

## Деплой

Проще всего — Vercel: подключите репозиторий, добавьте те же две переменные окружения.

## SEO и выбор языка

Канонический адрес сайта — `https://blablatravel.com` (`src/lib/seo.ts`).
Главная, карта и объявления имеют canonical, hreflang на шесть языков,
Open Graph и Twitter metadata. Поисковые запросы включены в видимый текст
главной и локализованные title/description. Личные разделы, вход, регистрация,
раздел знакомств и админка помечены `noindex`.

Приоритет языка: префикс URL → cookie `NEXT_LOCALE` → страна из
`x-vercel-ip-country` → язык браузера → английский. Заголовок страны
предоставляет Vercel; на другом хостинге потребуется аналогичная интеграция
с доверенным прокси. Таблица стран находится в `src/i18n/country.ts`.
Для Канады, Швейцарии и Бельгии используется язык браузера. Редиректы временные
и не кэшируются. Прямые ссылки `/ru`, `/en` и другие всегда сохраняют язык.

`/sitemap.xml` — индекс карт сайта: `/sitemaps/pages.xml` содержит 12 главных
страниц и карт, `/sitemaps/listings/0.xml`, `/sitemaps/listings/1.xml` и далее
содержат все доступные публично активные объявления на шести языках.
Каждая часть включает максимум 500 объявлений (3000 URL), с hreflang.
Индекс и объявления обновляются с интервалом кэширования один час. При ошибке
базы возвращается 503, а не успешный ответ с неполной картой. `/robots.txt`
ссылается на индекс. Неактивные объявления исключены из sitemap.
После публикации добавьте `https://blablatravel.com/sitemap.xml` в Google Search
Console и Яндекс Вебмастер и проверьте индексацию языковых страниц.

Проверка: `npm run build`, затем `npm run start -- -p 3100` и в другом терминале
`node scripts/check-seo.mjs http://localhost:3100`.

Если одновременно работает `next dev`, собирайте в отдельную папку:
`NEXT_BUILD_DIR=.next-seo npm run build`, затем
`NEXT_BUILD_DIR=.next-seo npm run start -- -p 3100`. Это предотвращает
конфликт сборки с файлами сервера разработки.

Главные страницы используют следующие основные поисковые формулировки
(это редакционный подбор, не данные о частотности запросов):

| Язык | Основные запросы |
| --- | --- |
| Русский | попутчик, найти попутчика, попутчики для путешествий |
| English | find a travel buddy, travel companions, travel partner |
| Español | compañeros de viaje, encontrar compañeros para viajar |
| Deutsch | Reisepartner finden, Reisebegleiter, gemeinsam reisen |
| Português | companhia para viajar, parceiros de viagem |
| Français | compagnon de voyage, trouver des compagnons de voyage |

Фразы используются в title, H1 и полезном тексте, без скрытых списков ключей.
На каждой главной есть четыре вопроса и ответа о планировании поездки,
HTML-ссылки на другие языки и JSON-LD `WebSite`. FAQ не обещает расширенных
сниппетов Google. Достижение конкретной позиции требует публикации,
индексации и дальнейшего анализа запросов в Search Console.

## Производительность

- Список из 20 чатов: 3 HTTP-запроса вместо 24. Последнее сообщение и признак
  непрочитанного получаются вместе с диалогами через ограниченные вложенные
  выборки PostgREST, без отдельного запроса на каждый чат.
- Оба меню используют одну realtime-подписку для индикатора непрочитанных.
  Проверка загружает не более одной строки; события объединяются, запросы
  отменяются при смене пользователя. Чужие диалоги исключаются явным фильтром
  участников, в том числе для администраторов.
- Отправка и получение сообщений не вызывают повторный рендер всей страницы
  с сервера. Превью меняются через realtime; серия событий чтения объединяется
  в одно обновление. Ввод текста не перерисовывает неизменившуюся историю чата.
- Переходы используют неблокирующий индикатор с задержкой 180 мс и серверный
  `loading.tsx`. Отправка сообщений не перекрывает экран.
- Публичные запросы карты используют кэш Next.js на 60 секунд.

Проверка запросов: `node scripts/check-chat-performance.cjs`. Флаг `--live`
дополнительно проверяет совместимость запросов с Supabase анонимно, без записи
данных. Число запросов проверено автоматически; сравнение времени работы
авторизованных сессий на реальных устройствах пока не проводилось.

## Письма о новых сообщениях

Реализация подготовлена для Resend. Письма не начнут отправляться до настройки
ключей, миграции и планировщика. Пример оформления: `docs/email-preview.html`.
HTML использует таблицы, встроенные стили и текстовую версию без внешних картинок.

1. В Resend подтвердите домен отправителя и создайте ключ отправки. На хостинге
   задайте `RESEND_API_KEY`, `EMAIL_FROM` (например,
   `BlaBlaTravel <notifications@blablatravel.com>`),
   `SUPABASE_SERVICE_ROLE_KEY`, `EMAIL_NOTIFICATIONS_SECRET` (случайная строка
   минимум 32 символа). Все эти значения серверные, без `NEXT_PUBLIC_`.
2. Выполните `supabase/message_email_notifications.sql` в Supabase SQL Editor.
   Он добавляет закрытую RLS-очередь, триггер INSERT сообщений и функцию выдачи
   задач с блокировкой. Существующие сообщения не вызывают рассылку.
3. Опубликуйте приложение. В Supabase включите Cron и pg_net. В Vault создайте
   `message_email_url` со значением
   `https://blablatravel.com/api/notifications/email` и `message_email_secret`
   с тем же значением, что `EMAIL_NOTIFICATIONS_SECRET` на хостинге.
4. Выполните `supabase/message_email_schedule.sql`. Cron вызывает обработчик
   раз в минуту; один запуск обрабатывает до 3 писем последовательно.
5. Проверьте на двух своих тестовых аккаунтах: новое сообщение → новая задача
   в `message_email_jobs` → `sent_at` после принятия письма Resend → письмо во
   входящих. `sent_at` означает принятие провайдером, а не гарантированную
   доставку во входящие; отказы доставки видны в Resend.

Получатель определяется по участникам диалога, email берётся из `auth.users`.
Уведомления направляются только на подтверждённый email. Очередь сохраняет
адрес и язык на момент сообщения. Язык записывается при регистрации и при
посещении сайта авторизованным пользователем; для старых аккаунтов без языка
используется английский. В письме нет текста переписки. Кнопка ведёт в диалог;
после входа пользователь возвращается в него. Клиент не может задать адрес
получателя или вызвать отправку без серверного секрета.

Почтовый запрос не задерживает чат. При ошибке есть до 6 попыток с увеличением
интервала. Атомарная аренда задачи и Resend Idempotency-Key предотвращают
повторы в окне повторных попыток; тело письма сохраняется до первой отправки.
Автоматически отправляются только задачи моложе 20 часов (меньше 24-часового
окна Resend). Задачи с `attempts >= 6` или старше 20 часов без `sent_at` требуют
проверки оператором; не сбрасывайте их вслепую — письмо могло быть принято
провайдером до сбоя записи результата. При высокой нагрузке нужно увеличить
пропускную способность обработчика с учётом лимитов почтового сервиса.
Очередь содержит email: доступ разрешён только серверной роли. Удаление
сообщения/аккаунта удаляет связанные задачи. При эксплуатации настройте
срок хранения успешно отправленных задач согласно правилам проекта.

Тест без реальных писем: `node scripts/check-email.cjs`. Он проверяет шаблоны
шести языков, безопасный возврат после входа, секрет обработчика, сохранение
payload, повторы и ошибки провайдера, а также создаёт HTML-пример.
Миграция и доставка реального письма проверяются отдельно после подключения.
